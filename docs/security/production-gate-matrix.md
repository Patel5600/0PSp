**External cryptographic audit:** NOT PERFORMED, and deliberately tracked separately as requested. That does not convert missing implementation or proof obligations into GO.

## Status rule

Every gate below has a binary production status. **GO** means the exact gate described has adequate implementation and evidence for its limited scope. It does not automatically approve the complete protocol. **NO-GO** means the release criterion is not met; a green unit-test job, user risk acceptance, or an external-audit deferral cannot substitute for missing security behavior.

## Immediate next sequence

1. **Close the Aurora transcript wire-format blocker first:** for the pinned `gf64 + binary_hash_digest` pairing, implement or formally choose a canonical, bounded serializer/deserializer that includes every verifier-critical transcript field, especially `proof_of_work_`; add round-trip, verifier-acceptance, fuzz/property, truncation, malformed-length, trailing-byte, and mutation tests. The current upstream implementation explicitly reports this pairing as unimplemented. Do not rely on in-memory proving as proof of deployable proof transport.
2. **Aurora executable closure:** pin and build all dependencies in an isolated environment, run the upstream suite, verify the actual binary-field and ZK paths, then prove/verify a tiny SHAKE256-384 subrelation with adversarial public-input/digest/padding mutations. Re-review masking and degree bounds against current ZK analyses and calculate concrete QROM security before scaling. CHp4.23 is only a deterministic circuit-shape estimate.
3. Freeze authorization policy and exact public-key/signature codecs against a stated adversary model; establish whether the chosen PQ signature verification can fit the proof system or must be a separate, explicitly public authorization predicate.
4. Implement one shared-witness relation covering canonical TxFieldsV2/TxDigestV2, CommitV2 opening, 63-level membership, same-witness NullifierV2, range-safe value conservation, output commitments, and authorization. Prove adversarial statement substitutions fail.
6. Run a full internal threat-model audit on one release SHA, fix all P0/P1 findings, perform live-chain and crash/reorg/power-loss recovery tests, then stamp per-gate decisions. External audit remains explicitly NOT PERFORMED.

**Current decision remains NO-GO.** The way to change it is evidence that closes each required gate, not stronger wording in a README. External audit may remain unperformed, but missing proof soundness, custody authorization, or value conservation cannot be waived while still honestly describing the system as end-to-end private spend.
