# Production-1 limitations

**Current scope:** Production-1 verification is enabled only for the local synthetic test-value profile after `make production-check` passes. Public testnet value and Mainnet live value remain **NO-GO**; Mainnet verification is hard-disabled. This does not claim a public L2 deployment or authorize real-value transfers.

- **Proof backend and soundness:** OpenVM 2.0.2 at pinned git revision `59a69b8b0cbee7011ac978e4cc07707ee3681944` is the only active backend. The active constructor is `app_params_with_100_bits_security(MAX_APP_LOG_STACKED_HEIGHT)`, which declares a 100-bit application RBR target. The 102.63/100.98-bit calculations in `BENCH.md` describe proposed parameter profiles, not the active profile. The active composed bound is unknown; composed ≥128-bit post-quantum security is **NOT CLAIMED**. The manifest pins the verifier/build inputs and rejects unreviewed drift.
- **Proof privacy:** Label: **proof of knowledge under the pinned OpenVM verifier assumptions; zero-knowledge / witness hiding NOT established**. Prover-trace masking and an independent Fiat–Shamir/QROM composition bound are not established. This is distinct from Phase A worker operator access to plaintext witness.
- **Witness privacy and operator trust:** Phase A is a single-tenant worker over TLS with bearer authentication, concurrency one, bounded requests, no witness logging, and mutable request-buffer wiping. The worker and operator process plaintext witness and can inspect or retain it. This is not witness hiding from the operator. Python/OpenVM internal copies and all operating-system swap/crash-dump paths are not proven wiped. Phase B attested TEE and MPC proving are not implemented.
- **Relation scope:** Authorization is knowledge of `nk` opening the note key commitment. Threshold authorization is not implemented. The relation is Zcash-style namespace-scoped Merkle membership plus CommitV3 and HMAC-SHA3-384 NullifierV3; Monero ring signatures, RingCT, LORTs, and decoy-set privacy are absent.
- **Relation identity:** `params_id` is serialized in TxFields and included in the public digest. `relation_id` is selected by the pinned circuit ID/VK manifest, not serialized as a separate TxFields field; making it a public statement field requires a new relation version and regenerated OpenVM artifacts.
- **State and recovery:** SQLite provides an append-only local nullifier set, unique outputs, atomic state transitions, and a 256-anchor history ring. Production-1 bootstrap is deterministic synthetic local-faucet data. No external finalized-state provider, public-chain contract/faucet, distributed consensus, chain reorg recovery, custody, or backup/recovery flow is included.
- **Root and issuance boundary:** Pure proof verification checks a proof against the root supplied in its public statement; it does not authenticate root finality. The local ledger separately rejects roots outside its local retained ring, including stale/wrong roots, but this is not authenticated public-chain state. Synthetic issuance authorizes only the explicit bootstrap fixture commitments inserted into the initial tree. No public deposit/mint authorization is implemented.
- **Public testnet deployment:** `CONTRACTS_MISSING` — repository inventory found no spend-pool Solidity/Vyper contract to deploy. Phase 6 public L2 stress/faucet was therefore not started; Production-1 evidence is local synthetic test value only.
- **Client and device scope:** The client builds the witness and verifies the OpenVM proof locally; the worker proves; the ledger independently re-verifies. Mobile proving is out of scope. Mobile verification is not established as feasible for the measured proof profile.
- **Measured cost:** The named WSL2 host produced a 660,320-byte full spend proof in 415.161 seconds in the SDK measurement; the full worker→client→ledger run measured 676.077 seconds proving, 337 ms client verification, and 3,011,764 KiB peak RSS. See [BENCH.md](../BENCH.md) for hardware, separate checker verification, and artifact hashes. These are single runs, not a capacity guarantee.
- **Audit and release:** External cryptographic audit is **DEFERRED** and has not been performed. No mainnet caps are asserted because mainnet is disabled. Mainnet requires separate review of the security bound, witness privacy, state/finality/recovery, custody, and audit gates.
- **Primitive test boundary:** The pure `verify_production1_spend` API returns verified public fields without changing state; ledger application separately checks the allowed anchor and nullifier/output uniqueness. The production host-reference API enforces 1-in/1-out and depth-63 only. Its field-mutation tests and the Rust guest mutation tests establish predicate rejection for the fixed vector, not a universal soundness or zero-knowledge proof.
- **Threat model:** [Production-1 trust boundaries and adversaries](../0psp-threat-model.md) describe honest-but-curious and malicious operator outcomes, client abuse, local database rollback, and artifact substitution.
- **Separate stack:** MAMA40 is a separate content-AEAD stack and is not used by this spend or worker.
